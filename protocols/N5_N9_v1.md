# N5–N9 v1: confirmation, explanation, prediction and applications

This protocol extends the completed MM-first N1–N4 study without changing its code snapshots, input suites, thresholds or results. `configs/campaign_n5_n9_v1.json` fixes the numerical contract, candidate budgets and experiment order. `configs/shapes_heldout_v1.json` reserves 16 geometries before N5 tuning. All execution decisions, source/configuration hashes, failures and commits remain in immutable run directories.

The original N1–N4 allocation was lost. N5–N9 therefore constitute a **new v5e cohort**. Comparisons are interleaved within that cohort; old and new timings are not pooled. Keep this allocation for N5–N9, defer any fresh-v5e replication until N9 has finished, and defer all v6e work until the v5e stages and their replication are complete. No simultaneous TPU timing is permitted. The root orchestrator owns every execution, source snapshot and post-execution commit.

## Evidence motivating these choices

The initial fixed-tile Strassen implementation beat the quadrant-cubic diagnostic on many shapes but did not establish a win against the stronger full-tile cubic or native compiler baseline. Larger tiles changed this picture in the screening data. N3 identified measurable effects of buffer storage and product order. These results motivate a stronger full-tile cubic output-accumulator variant and independent bounded tuning of both algorithms.

N4 found a serious scope limit: Strassen failed all 24 synthetic cancellation cases with roughly 0.53 relative L2 error while classical baselines passed. This failure remains in the record. Passing Gaussian or real-weight-with-synthetic-activation checks cannot establish safety for arbitrary model activations. Neither shape nor a performance classifier certifies numerical accuracy. The existing synthetic gate remains unchanged.

## N5: fair independent tuning and fresh confirmation

Use 16 exposed shapes from the original suite: four square scales; independent M/K/N changes; a deeper rectangular case; small-M cases; two nonaligned cases; and Qwen, Mistral-width and Gemma-width projections. The exact IDs are frozen in the new config. Every family gets **20 candidate attempts per shape**, including infeasible and numerically failing attempts.

- Full-tile cubic gets plain and output-accumulator variants over ten tiles.
- Strassen gets four product-order/accumulator variants over five tiles.
- Native XLA remains the practical baseline on the original dimensions.

Thus cubic receives a wider tile grid rather than inert product-order variants for its one-product-per-panel implementation. Equal attempt budgets do not imply exhaustive or equally complex search spaces; report this limitation. Candidate grids are explicit and identical in N5 and the later held-out alternative screen. There are 640 custom candidate attempts across the 16 training shapes, plus native observations. Failed attempts count; no replacement candidates are inserted for one family.

Screen with 2 warmups and 7 synchronized repetitions, retaining both complete-call and prepared-kernel scopes. An eligible candidate must pass the numerical gate in both scopes and complete all repetitions. Choose independently by complete-call mean, breaking exact ties by candidate ID. Save every candidate and immutable `selections.json`; a family with no eligible candidate has a null selection, not a silent fallback.

In a separate fresh process on the same allocation, confirm the selected cubic, selected Strassen and native arms using 5 warmups and 30 interleaved repetitions in both scopes, with a new Gaussian seed. All arms use the same input arrays and original output shape. Compilation and host transfer remain outside the timing; per-call device padding, layout work and output cropping remain inside the complete call. Preparation metadata and the reusable-input interpretation of prepared-kernel timing remain explicit. This is a bounded stronger-baseline comparison, not a proof of best possible cubic or Strassen performance.

## N6: profile measured wins, ties and losses

Classify each eligible N5 confirmation shape by its complete-call paired Strassen-versus-selected-cubic CI95: wholly above one is a win, wholly below one a loss, otherwise inconclusive. In each present class, sort by `M*K*N` then shape ID and select the lower median. Select at most three shapes. If a class does not exist, record it as absent; do not manufacture a win or substitute a different comparison.

For each representative, retain the frozen selected cubic, selected Strassen and native implementations. Measure ordinary synchronized latency before and after profiling. Collect **real JAX TPU traces**, two captures per arm, eight synchronized calls per capture, reversing arm order in the second block. Retain XPlane and Perfetto artifacts and all failures. Extract complete module durations only from the uniquely identified TPU `XLA Modules` track, requiring the expected eight invocations. Do not add nested/overlapping operation durations together or replace ordinary latency with instrumented profiler wall time.

Save compiled HLO text where exposed, compiler memory analysis and compiler cost analysis. These are compiler diagnostics, not measured peak device memory or executed memory traffic. The previously qualified profiler gives device duration traces; it does not expose a validated MXU/vector hardware-utilization counter. Record unavailable counters explicitly. Static instruction scheduling and coissue opportunities must never be described as measured overlap.

Use official v5e specifications—197 BF16 TFLOP/s and 800 GiB/s HBM bandwidth per chip—to produce clearly labeled optimistic roofline estimates. [Google v5e specifications](https://docs.cloud.google.com/tpu/docs/v5e), accessed 2026-09-19. Use compulsory original-input/output bytes and padded matrix-product work; separately report an unshared tile-traffic estimate and source-level vector-operation counts. Such estimates omit vector timing, extra buffering/traffic, launch overhead and nonideal utilization. Useful `2*M*K*N / elapsed` is an effective MM throughput, not executed Strassen FLOP throughput or utilization.

## N6a: freeze an interpretable selection rule

Train only on the new cohort's N5 confirmation, never on N7 measurements. N1–N4 informed the preregistered experiment design; their timing rows are not pooled with this cohort. The rule is a small nearest-prototype table in log2(M,K,N), with the following fixed safeguards:

1. A training shape is labeled Strassen only when its numerical checks pass and its paired CI95 lower bounds exceed **1.01** against both native and independently selected cubic. A cubic label requires the same margin against native. Otherwise label it native.
2. For a new shape, choose the nearest training prototype in Euclidean log2-dimension distance. Ties break by shape ID. Use its frozen algorithm, variant and tile without tuning the new shape.
3. Use a custom path only if M≥256, K,N≥512, distance≤1.75 and padded volume/original volume≤1.5. Otherwise use native.
4. An explicit caller-supplied input scope of `gaussian_synthetic` is required for a custom path. Unknown data, declared cancellation tests, actual activations and real-weight scopes default to native. This declaration is not an automatic property inferred from shape, and it is not a theorem about all Gaussian draws. Every evaluated output still receives the unchanged numerical gate.

Report leave-one-training-shape-out family agreement as a descriptive cross-validation check. Do not tune thresholds or choose a different model after seeing this result. Borrowing a tile from another shape can change latency; therefore family agreement is not claimed to be measured dispatch latency or deployment regret.

Serialize the rule, parameter values, training shapes, reserved held-out shapes, input-scope restriction, source identity and training artifact hashes into an exclusively created `selector.json`. Freeze its bytes and hash **before any N7 timing or correctness observation**. The rule may validly choose native for every tested shape; this is a finding, not a reason to relax safeguards.

## N7: genuinely held-out geometry and frozen-policy evaluation

The reserved suite contains 16 shapes: four intermediate square sizes, four new rectangles, two small-M cases, two nonaligned cases and four new Qwen/Mistral/Gemma projection/token-row combinations. No `(M,K,N)` appears in N1–N4 or N5 training. The shape definitions are inspectable in advance; their measurements cannot be used by the rule.

After the selector is frozen, independently tune cubic and Strassen on these shapes with the same 20-attempt family budgets. This supplies a test-time comparison oracle. Its selections and measurements do not update the rule. Record the frozen selector hash in every held-out run and reject any training/held-out overlap.

Then measure the frozen selector route, selected held-out cubic, selected held-out Strassen and native in the same paired rounds, using 5 warmups and 30 repetitions and a fresh Gaussian seed. Report both timing scopes, all numerical failures/compilation errors, chosen family and tile, decision reason, and latency regret relative to the fastest numerically eligible independently measured alternative. Tuning costs are separate. The selected route can duplicate another arm; label this rather than implying a distinct algorithm. CPU rule evaluation overhead is recorded separately and not silently included in a kernel measurement.

Perform a separately labeled fresh-v5e fixed-policy replication only after all original-cohort N5–N9 work is complete. Never retune the rule on that replication or pool cohorts without reporting them. v6e is a later replication stage, not part of the initial v5e claim.

## N8: subsequent operations and fusion

The application runner uses fixed, separately archived configurations for MM plus SwiGLU and MM plus residual on small, medium and Qwen3-32B-scale LLM projection geometry, at M=512/2048. Compare native joint graphs, full-tile and quadrant cubic, and Strassen, separating unfused/fused and early-finalization variants where implemented. Include a matched-tile ablation and the selected policy where an exact shape is available. Qualify every arm under a common arithmetic contract before timing. Report preparation separately and include it in the complete-call scope.

This stage asks whether downstream vector work adds gains beyond pure MM. It does not certify a model's output quality. Exact implemented arms, output dtype, gates and shapes are frozen in the application config rather than inferred from the names of historical kernels.

## N9: real applications and natural-text quality

The intended application study uses Qwen3-0.6B and public Mistral-7B-v0.3. Attempt an additional official Gemma checkpoint only when access is already legitimately available; do not accept license terms or substitute a mirror to manufacture coverage. Record an unavailable model transparently.

Use actual checkpoint weights and real tokenized WikiText2 test text. The planned bounded quality cohort is 32,768 contiguous tokens per tokenizer in 1,024-token windows, with the precise scored count, source revisions and token hashes saved. Freeze native/cubic/Strassen site policies and quality thresholds before running. Report NLL/perplexity, KL, top-1 agreement and actual-layer activation timing, including failures. Small synthetic activation checks are not substitutes for this stage.

A streamed full-forward run, a resident layer measurement and device-only compute are different timing scopes. Keep them separate, include weight movement in any claimed full-forward wall time, and do not infer end-to-end serving speed from resident kernel timings. If an implementation, resource or access limit prevents a planned quality evaluation, retain it as incomplete and describe the narrower completed result.
