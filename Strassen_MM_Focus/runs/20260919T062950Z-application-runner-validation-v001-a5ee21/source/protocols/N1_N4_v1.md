# N1–N4: matrix multiplication first, v5e campaign v1

This is a new study in `Strassen_MM_Focus`. Historical kernels may be reused with attribution, but historical measurements are not results of this campaign. The protocol is fixed by `configs/campaign_v1.json` and `configs/shapes_v1.json`; source and configuration hashes must accompany each immutable execution. This document describes the intended experiment, not a claim that a run has occurred.

## Common question and scope

For `A[M,K] @ B[K,N]`, when does a one-level Strassen implementation offer useful speed or accuracy tradeoffs relative to classical multiplication and JAX/XLA on one v5e device? Vary M, K and N independently rather than repeatedly benchmarking one model projection.

The initial suite has 44 shapes:

| Family | Count | Purpose |
|---|---:|---|
| Square | 5 | Side lengths 512, 1024, 2048, 4096, 8192 |
| Independent axes | 6 | Move one of M/K/N to 512 or 8192, holding the others at 2048 |
| Aspect ratios | 6 | All permutations of M/K/N = 512/2048/8192 |
| Small M | 4 | M = 1, 8, 64, 256 with K=N=2048 |
| Nonaligned | 4 | Odd sizes that force nontrivial padding and cropping |
| LLM projection geometry | 19 | Qwen3-32B, Mistral-7B-v0.1 and Gemma-2-9B projection widths with varied token rows |

The previous `(8192,5120,51200)` Qwen gate/up geometry remains an anchor, not the only main result. Shape order is always **M,K,N**; tile order is always **BM,BN,BK**. These orders differ deliberately and must never be inferred from position alone in an unlabeled record.

All N1–N4 input arrays are synthetic. LLM geometry does not mean checkpoint weights, real activations, or a model-quality experiment. The concatenated gate/up projection is matrix multiplication only: it includes no SwiGLU or GeGLU. The `kv` label means the shape of one key **or** one value projection, not a concatenated K+V matrix.

## Machine and execution control

1. Use one v5e allocation and one selected device for the campaign. Do not run timing jobs simultaneously. Agent activity must not cause concurrent TPU work.
2. Record allocation identity, device ID/type, host/process, runtime image, JAX/JAXLIB/libtpu versions, compiler/runtime flags, and source/configuration hashes. Record unavailable identity fields as unknown; never claim verified chip identity from the device type alone.
3. Seal an environment fingerprint after the smoke run. A changed allocation, runtime, package, flag, or device produces a separate cohort. Do not silently pool such results.
4. Compile and transfer inputs outside the timed region. Synchronize inputs before measurements and every output at the end of each timed call. Retain individual chronological timings with arm order and scope. Use seeded balanced interleaving rather than timing one arm for a long uninterrupted block.
5. Smoke uses 2 warmups and 5 measured repetitions. N2 screens use 2 warmups and 7 repetitions. N1/N3 confirmations use 5 warmups and 30 repetitions. N4 characterizes accuracy and is not a performance race.
6. Preserve every attempted case, including compile failures, memory failures, unsupported configurations, numerical failures and interruptions. A failed candidate consumes its search attempt; do not substitute an extra candidate for only one algorithm.
7. Use immutable UTC/unique run directories. Commit the source/protocol snapshot before the first execution, and commit artifacts after **every** execution, including a failed execution. A retry receives a new run ID and links back to the earlier run. Do not overwrite an earlier run's code snapshot, result rows, logs or summary.

The root orchestrator owns archiving, execution and commits. This protocol does not authorize a protocol-writing agent to execute a benchmark. v6e is a later replication cohort and is disabled in the v1 configuration.

## Arithmetic contract and baselines

Inputs are BF16, matrix-product accumulation and output are FP32. Strassen pre-additions/subtractions occur in BF16; their rounding is an observed accuracy cost. Reference calculations use the exact BF16-quantized inputs cast to host FP32. Thus this is not an experiment about input quantization error. Historical BF16-output measurements are not directly comparable.

| Arm ID | Kernel algorithm | Role |
|---|---|---|
| `native_xla` | `native` | Ordinary compiled JAX multiplication, precision explicitly recorded |
| `cubic_basic` | `cubic_full`, `plain` | Straightforward full-tile classical multiplication; practical baseline |
| `cubic_quadrant` | `cubic_quadrant`, `plain` | Eight sub-products with matching split structure; diagnostic control |
| `strassen_basic` | `strassen`, `plain` | One Strassen level within each tile product; seven sub-products |

A compiler still optimizes all these implementations. “Basic” means no explicit experimental product interleaving or output-accumulator variant, not scalar/naive code. The full-tile cubic control prevents a favorable comparison against only an unnecessarily split cubic implementation.

For custom kernels, zero-pad required extents and crop to the original output. Never drop small-M or nonaligned shapes merely because they are poor fits. If a shape is unsupported, record that explicitly. Record original and padded dimensions and padding ratios, and compute useful GFLOP/s from original `2*M*K*N`, not padded work.

Two timing scopes are required:

- **Complete call:** device inputs in their ordinary original shapes through required preparation, multiplication, and output crop. This is the headline comparison. Host transfer and compilation are excluded and labeled separately.
- **Prepared kernel:** already prepared and synchronized device inputs through the multiplication kernel. This answers the reusable-input question; it does not imply preparation is free. Record preparation details and the reuse assumption. If a compiler fuses or elides preparation, do not attribute a measured total-call difference to a standalone copy that did not occur.

Native XLA operates on the original dimensions. Forcing it to use custom-kernel padding would handicap the practical baseline. The custom cubic-quadrant/Strassen pair supplies a like-for-like padded diagnostic comparison.

## Stage order and bounded budgets

Run a small smoke cohort first: `square_512`, `small_m_8`, and `tail_513`, all four arms at tile `(256,256,256)`. Calibrate compile/runtime cost and check outputs, padding/cropping, record capture and immutable archiving. If infrastructure or kernel correctness is broken, preserve that execution and fix it under a new snapshot before proceeding. Do not change the scientific thresholds because a candidate fails.

After smoke, order cases by conservative estimated live device bytes and run the largest prior anchor last. Keep only the inputs, executable and result needed for the current comparison. Use an 8 GiB conservative estimated live-buffer budget; this is a precautionary estimate, not a measured hardware-memory limit. Kernel VMEM limit is fixed at 48 MiB for v1. Any allocation-wide runtime flag must remain fixed and recorded for every arm.

### N1 — untuned broad comparison

Run all 44 shapes, four arms, shared custom-kernel tile `(256,256,256)`, Gaussian inputs and seed 20260919. There are 176 arm–shape cases, each measured in both scopes. This establishes implementation behavior and padding costs before tuning. Report speed and numerical validity; an invalid result is not a valid win.

N1 cannot establish the best achievable performance of either algorithm: it intentionally uses a fixed initial tile. It should make that limitation visible.

### N2 — matching tile screen

Use the 12 preregistered representative shapes listed in the config. Evaluate each of these six tiles for full cubic, split cubic and Strassen:

`(256,256,256)`, `(512,512,256)`, `(1024,512,512)`, `(512,1024,512)`, `(1024,1024,512)`, `(2048,2048,512)`.

There are 216 arm–shape–tile attempts. The candidate list and number of attempts are identical for each algorithm; failed compiles count. Record both timing scopes, memory/padding properties and numerical gates. This reveals tile sensitivity and feasible regions. An N2 minimum is a screen observation, not a confirmed winner or a final N5 tuning result. Do not derive a final generalized selection rule from these same observations and then call them held-out validation.

### N3 — fixed-tile optimization ablations

Use the six preregistered shapes and tile `(1024,1024,512)`. For each split algorithm, compare four variants:

1. `plain`: baseline product order and four separate output-quadrant accumulators.
2. `interleaved`: change product order only. Strassen order is `[4,6,5,2,7,3,1]` instead of `[1,2,3,4,5,6,7]`; split cubic uses round-robin products.
3. `output_accumulator`: retain baseline order but accumulate into the FP32 output tile instead of four scratch quadrants.
4. `interleaved_output_accumulator`: combine the two changes.

There are 48 arm–shape–variant cases. All use the same dtype, tile, input, output and memory limit. Report each individual change and the combination; the combination need not equal the sum of individual gains. Compile/memory failures remain results. No adaptive fallback tile is allowed; a changed common tile is a new protocol version. N3 excludes activation fusion and early finalization, which belong to later N8.

### N4 — numerical stress characterization

Use the eight preregistered shapes, four baseline arms, five distributions and three seeds (20260919, 20260920, 20260921): 480 numerical arm–shape–distribution–seed cases. N3 variants already receive their routine numerical checks; N4 deliberately holds the arithmetic baseline fixed to characterize shape and input effects.

The input generator follows `distributions_v1.json`. Save generator identity, seed, profile parameters and hashes where practical. Do not regenerate different inputs for different arms. Generate in host FP32, then round once to BF16 before calling any arm or reference. All values should remain finite; a generator producing nonfinite inputs is an input failure, not a kernel error.

The five profiles are normal, uniform, a range of powers-of-two scales, sparse large outliers, and almost cancelling contributions across halves of K. They are diagnostic synthetic stress cases, not a model-data distribution or an exhaustive stability guarantee.

Host FP32 reference is full only if both `M*N <= 1,048,576` and `2*M*K*N <= 2,000,000,000`. Otherwise use the cross-product of up to 128 deterministic sampled rows and 128 sampled columns, including boundaries, and use **all K** for every reference element. Save the sampled indices. Label sampled statistics as sampled; they do not establish a whole-output maximum-error guarantee.

All arms have the same frozen eligibility gate:

`finite && relative_L2 <= 0.02 && max_abs_error <= 0.001 + 0.05 * max_abs_reference`.

Relative L2 uses denominator `max(||reference||_F, 1e-30)`. Also report RMSE, mean/median/99th-percentile absolute error, maximum absolute error, and normwise error. If whole-output finite scanning is available, retain it separately from sampled-reference error checks. A cancellation case can legitimately fail the relative criterion even with small absolute error; report both rather than relaxing the gate. This gate is a campaign-level numerical screening contract, not a theorem or an LLM-quality threshold.

Real checkpoint weights/activations are **deferred** until verified artifacts exist. A later cohort must record checkpoint revision, tensor name, input/weight hashes, dtype, and activation provenance. Synthetic matrices with Qwen/Mistral/Gemma dimensions must not be described as a real-weight experiment.

## Reporting and interpretation

Maintain an append-only attempt ledger with experiment, original/padded shape, arm, tile, variant, distribution, seed, precision, timing scope, repetitions, environment/source/config fingerprints, reference scope, metrics and explicit status. Preserve full error diagnostics in run logs. Summaries may be regenerated into a new timestamped/versioned artifact; old artifacts are not replaced.

Report wins, ties, losses and infeasibility by shape family. Never report only the fastest Strassen cases or silently exclude failed accuracy gates. Where confidence intervals are used, pair by interleaved repetition and retain the bootstrap seed/method; do not treat the two timing scopes or multiple repetitions as independent shape observations. N1–N4 support exploration and controlled ablation; final independent tuning, fresh confirmation and held-out selection-rule evaluation remain N5–N7.

## Explicitly deferred note

Two-level Strassen is a useful later experiment to justify recursion depth. It is **not** implemented or executed by this N1–N4 protocol. Keep this note in the campaign without widening the initial execution scope. v6e replication, model-quality testing, activation fusion and end-to-end model performance are likewise later stages.
